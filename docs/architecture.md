# Architecture — FSBM Library

## Beta scope

The public beta exposes only Informatique Appliquée at the Faculté des Sciences Ben M'Sik and semesters S1–S6. The interface is French-only. Other programmes are not exposed in public navigation.

## Components

- **Astro** generates the static public website and administration shell.
- **TypeScript browser modules** implement search, requests, catalogue rendering and administration interactions. React was removed because the supplied UI does not require a component runtime; this keeps the client bundle and dependency surface smaller.
- **Tailwind CSS** is available for utility styling; the visual system is implemented in the global stylesheet.
- **GitHub Pages** hosts the static frontend.
- **Cloudflare Workers** provides the API and enforces privileged operations.
- **Cloudflare D1** stores academic data, resource metadata, requests, admin accounts, sessions and audit records.
- **Cloudflare R2** stores private PDF files.

## Data flow

The browser reads the public catalogue and published resources from the Worker. Anonymous students can submit requests and download published PDFs. Administrators authenticate with the Worker; the Worker checks roles before any privileged operation. Resource records are created as drafts, the Worker validates and stores the PDF in R2, and an administrator explicitly publishes the resource.

## Security boundaries

- No Cloudflare credentials or administrator secrets are included in the frontend bundle.
- R2 writes and reads are mediated by the Worker; the bucket must remain private.
- Admin passwords are PBKDF2-SHA-256 hashes. Session tokens are random opaque values; only token hashes are stored in D1.
- Administrator sessions use Secure, HttpOnly, SameSite=Lax cookies. Use a frontend custom domain and Worker custom domain under the same registrable domain to avoid third-party cookie blocking.
- Mutating API requests require an exact allowed Origin. CORS is restricted to the configured public origin.
- Resource object keys are generated by the Worker, not from user-provided filenames.
- Uploaded files are PDF-only, signature-checked and size-limited. Production operators should add malware scanning if required by institutional policy.
- Owner-only actions are enforced server-side, not merely hidden in the interface.

## Extensibility

The data hierarchy is generic: faculty → programme → semester → module → resource. The beta seeds only the Informatique Appliquée programme. Additional programmes can be introduced through future administrative workflows without adding programme-specific database tables.
